# 核心购买链路用例改造计划

目标：让测试验证明确业务规则、独立预期与失败副作用，并据真实代码形成面试教学材料。
范围：接口用例、测试准备与运行配置、用例文档；不为测试通过擅改被测业务规则。
依据：ISTQB 黑盒测试技术（等价类、边界、状态迁移）；pytest 官方参数化及失败/跳过文档。

## 执行步骤

- [ ] 在独立 MySQL 库、独立端口启动系统，运行原接口基线。
- [ ] 改造数量边界：负数/零、1、库存前一位/等于库存/超过库存；累计加购合法与拒绝；用 DB 检查无副作用。
- [ ] 改造正常链路：下单前独立计算金额；分阶段检查库存、父子单、明细及购物车；使用 Decimal 精确比较金额。
- [ ] 补充下单库存变化、多商品失败整体回滚、已支付重复支付、部分收货、支付失败跨店子状态。
- [ ] 并发抢最后一件：两个独立买家先备好购物车，屏障同时请求；精确要求一个成功一个库存不足，核对订单与库存守恒。
- [ ] DB 不可达时报准备错误；Docker 测试进程显式连接 sut 使用的数据库；消除按订单列表末项识别订单。
- [ ] 运行改造接口、UI；临时注入金额计算/库存回滚缺陷，确认关键测试确实失败，然后恢复原业务代码并回归。
- [ ] 独立代码评审并修复重要发现；同步用例说明、面试材料与两处进度，开始逐步讲解真实设计过程。

验证命令：`.venv/Scripts/python.exe -m pytest api ui -q`，运行前设置专用 DB_NAME 与 BASE_URL；临时故障在内存启动器中注入，不提交故障代码。
补充检查：`git diff --check`；确认无跳过、测试数量有来源；检查 `git diff -- server/` 为空。
