# 性能复验环境检查清单

> 配套 [复验方案](../PERF_TEST_PLAN.md)、[问题核对](PROBLEMS.md) 和 [历史报告](report.md)。未勾选表示尚需核对，不代表已经执行。

## 运行前

- [ ] 记录代码提交、依赖、机器、数据库版本、运行参数和目标地址；基线与对照版本都可追溯。
- [ ] 功能测试与压测分服务、分专用库。账号前缀不能隔离清表重置；确认重置接口不指向压测数据。
- [ ] 功能故障注入用单服务进程；压测进程数按资源与目标选择。`PAYMENT_MODE` 在各进程不共享，不能把切换一次当作全部切换。
- [ ] 检查启动时环境变量、`.env`加载路径与实际路由。Windows子进程通常继承环境；已启动进程不会自动接收后续配置修改。
- [ ] 核对监听端口与目标进程命令，优先正常关闭自己启动的服务；必要时仅处理核实后的PID及子进程，不按名称结束所有Python进程。
- [ ] 铺账号、库存后，核对数量、合法登录、加购与下单样例及数据库变化；不把一次接口200当作全部业务正确。
- [ ] 保存数据库连接限制、线程缓存、应用线程池及每进程连接池参数。当前池最大150，4进程理论合计600，另计任务与其他连接；不照抄旧参数作为生产推荐。

## 执行中

- [ ] 记录虚拟用户数、升压速度、预热、稳定统计窗口和等待时间；零等待是压力模型选择，不是真实用户行为。
- [ ] 同步观察CPU、内存、连接与池等待、数据库锁等待；没有测量不把热点曲线差异当唯一因果。
- [ ] 分别记录登录、加购、下单的业务失败及响应样例。含错误档位也保留；调查其原因，不用“全程0错误才保留”丢弃数据。
- [ ] 档位间确认服务和数据恢复到约定状态；恢复失败则标注，不让后续档位悄悄沿用异常前置。

## 执行后

- [ ] 保存完整CSV、脱敏失败样例、命令与配置摘要；校验状态码之外的业务内容及库存/订单关系。当前脚本的这些校验仍有缺口。
- [ ] 同负载、同环境重复对照并报告波动；不同用户数峰值比单独展示，失败请求不计作成功订单吞吐。
- [ ] 标明未验证项和原因未知项，例如历史500用户池化下单213次HTTP400；不设必须提升某个倍数的验收目标。
- [ ] 正常停止本轮启动的进程，核对目标后清理本轮临时产物，保留原始测量证据。

判断性能结果需要结合成功率、业务正确性与资源条件。例如接口返回很快但账号不存在造成401，只能说明失败请求处理得快，不能说明成功登录能力提高。
